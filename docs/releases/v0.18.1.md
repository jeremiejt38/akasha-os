# v0.18.1 — Akasha Aura, corrections de rendu trouvées en validation réelle

> Suite immédiate de `docs/releases/v0.18.0.md`, même session. Patch découvert et livré en testant
> le jalon 1 d'Akasha Aura directement sur le Raspberry Pi (PixelCamera + `kodi-send`), en autonomie.

## Ce qui est corrigé

Deux bugs de rendu invisibles en relecture de code, découverts uniquement en testant sur le vrai
device :

- Les onglets utilisaient `<control type="radiobutton">` : Kodi dessinait son icône native de
  bouton radio par-dessus notre style personnalisé. Passé à `<control type="button">` — la
  sélection d'onglet est pilotée entièrement par `Window.Property(AuraActiveTab)`, pas besoin de
  sémantique radio.
- `texturenofocus colordiffuse="00000000"` (texture blanche rendue transparente par alpha) ne
  masquait pas réellement la texture sur ce moteur de skin : une boîte blanche restait visible
  derrière les onglets non focalisés. Supprimé `texturenofocus` : les onglets non focalisés
  s'affichent en texte simple (l'onglet actif garde son fond bleu `texturefocus`). Même correctif
  appliqué au contrôle `9000` (ancre de focus invisible pour la navigation `ondown`/`onup`), déplacé
  hors écran (`left=-100`) plutôt que rendu transparent par alpha.

Commit : `fix(aura): remove radiobutton/texturenofocus artifacts from tab bar`.

## Validation réelle effectuée

Déploiement + vérification autonome via PixelCamera (flux DroidCam pointé sur la TV,
`http://localhost:8088/frame`, voir `projects/pixelcamera.md` dans Atlas) et `kodi-send` :

- Redémarrage complet → Akasha Aura s'ouvre automatiquement après l'intro (onglet Divertissement).
- `kodi-send --action=Right` x2 → passage Divertissement → Jeux → App, contenu placeholder de
  chaque onglet affiché correctement, plus aucune boîte blanche parasite.
- `kodi-send --action=Back` → révèle l'accueil Kodi natif (Arctic Horizon 2) en dessous, confirmant
  le filet de sécurité prévu dans `docs/aura/decisions.md`.
- `kodi-send --action='RunScript(script.akasha.aura)'` → rouvre Aura (c'est exactement ce
  qu'exécute le keymap Home — non testable à distance avec un vrai appui physique sur la touche
  Home, seule la fonction sous-jacente a pu être vérifiée ainsi).
- Marqueur de version sur le device (`/storage/.config/akasha-os/VERSION` et en-tête du menu
  contextuel natif) confirmé à `0.18.1` après déploiement final.

## Incidents rencontrés pendant cette session (sans lien avec le code Aura)

- **WiFi du Pi tombé pendant le déploiement** : le Pi était en réalité relié par câble Ethernet, un
  fait qui n'était **pas documenté** dans `docs/hosts.md` d'Atlas (qui ne mentionnait que le WiFi).
  Après débranchement du câble (pour forcer un test), le WiFi ne s'est pas reconnecté tout seul,
  malgré le travail antérieur sur `wifi-watchdog.service`/`wifi-silent-agent.py`. Accès restauré en
  rebranchant l'Ethernet. **Non résolu** : la fiabilité de la reconnexion WiFi reste un point à
  investiguer dans une prochaine session — voir la mise à jour correspondante dans
  `docs/hosts.md` et `journal.md` d'Atlas.
- **GitHub Actions désactivé sur le repo** : `repos/jeremiejt38/akasha-os/actions/permissions`
  renvoyait `enabled=false`, bloquant silencieusement Release Please et le build d'image pour les
  deux premiers pushes de cette session (aucune erreur visible, juste aucun workflow déclenché).
  Réactivé via `gh api -X PUT repos/jeremiejt38/akasha-os/actions/permissions -F enabled=true`, puis
  re-déclenché avec un commit vide (`chore: re-trigger CI after GitHub Actions was found
  disabled`). Cause de la désactivation non identifiée — à surveiller si ça se reproduit sur ce
  repo ou d'autres.
