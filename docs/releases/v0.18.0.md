# v0.18.0 — Akasha Aura, jalon 1 (socle)

> Ce fichier est un résumé technique de session, pensé pour reprendre le travail dans une autre
> conversation (Devin CLI / Atlas) sans avoir à rouvrir tout l'historique de commits. Le changelog
> public condensé reste `CHANGELOG.md` ; ce document donne le contexte et les détails
> d'implémentation qui ne tiennent pas dans un message de commit.

## Contexte

Point de départ : l'utilisateur trouvait l'addon Plex utilisé jusqu'ici (`script.plexmod`, alias
"PM4K") peu fonctionnel/intuitif. Diagnostic (voir `docs/aura/decisions.md`) : PM4K est en réalité
une continuation du client Plex officiel open-source pour Kodi (maintenu par `pannal`,
`pannal/plex-for-kodi`) — donc déjà l'interface Plex authentique, pas une alternative. Aucun addon
Kodi existant ne peut être "plus fidèle à Plex" par construction (PlexKodiConnect, l'alternative la
plus citée, remplace l'interface Plex par une interface Kodi). Décision retenue avec l'utilisateur :
construire un accueil maison, **Akasha Aura**, plutôt que de chercher un autre addon.

## Ce qui est livré dans cette version (v0.18.0)

Uniquement le **jalon 1 (socle)** du chantier Aura décrit dans `docs/aura/roadmap.md` — la coquille
de navigation, sans données réelles :

- `kodi/addons/script.akasha.aura/` : addon `WindowXMLDialog`, fenêtre `Aura.xml` avec 3 onglets
  (`Divertissement` / `Jeux` / `App`, ids de contrôle `2001`-`2003`), navigation gauche/droite entre
  onglets, contenu **placeholder uniquement** ("a venir") pour chaque onglet.
  - `resources/lib/config.py` : module pur testable (`python3 -m unittest`), sans dépendance
    `xbmc*`. Gère la normalisation de l'URL du serveur Plex, la validation de configuration
    (URL + token), la construction des headers `X-Plex-Token`, et la résolution de l'onglet par
    défaut depuis les réglages.
  - `resources/lib/aura_window.py` : orchestration Kodi (dépend de `xbmc*`, non testable hors
    runtime Kodi) — gère la propriété `Window.Property(AuraActiveTab)` et le focus des boutons
    d'onglet.
  - Réglages (`resources/settings.xml`) : `plex.server_url`, `plex.token` (à renseigner
    manuellement sur le device, jamais commités), `tab.default`.
- `kodi/addons/service.akasha.aura/` : service `xbmc.service` (`start="startup"`) qui attend la fin
  du splash/intro (`service.akasha.splash`, fichier `/tmp/.akasha-intro-played`) puis ouvre Aura
  automatiquement — Aura devient l'accueil effectif sans toucher au `Home.xml` du skin Arctic
  Horizon 2 (voir `docs/aura/decisions.md` pour pourquoi ce choix plutôt qu'un patch de skin).
- `kodi/userdata/keymaps/akasha-aura.xml` : redirige l'action `Home` (clavier/télécommande) vers
  Aura, pour qu'il reste le point d'entrée permanent.
- `scripts/install.sh` : enregistrement/déploiement des deux nouveaux addons + du keymap, activation
  dans la base Kodi (`Addons33.db`).
- Docs : `docs/aura/spec.md` (fonctionnel), `docs/aura/decisions.md` (choix techniques + le
  diagnostic PM4K ci-dessus), `docs/aura/roadmap.md` (jalons restants).

## Ce qui n'est PAS encore fait (prochains jalons, voir `docs/aura/roadmap.md`)

1. **Rangées Plex réelles** : `plex_client.py` (API Plex directe : `/library/onDeck`,
   `/library/recentlyAdded`, hubs par genre) — actuellement, l'onglet Divertissement n'affiche
   qu'un texte placeholder.
2. **Bibliothèque complète** : vue liste avec recherche/tri/filtre par section Plex.
3. **Onglet Jeux** : grille de tuiles à partir de `skin-patches/shortcuts/games*.DATA.xml` —
   actuellement placeholder.
4. **Onglet App** : inventaire des addons installés (`Addons.GetAddons`), lancer/épingler/
   désinstaller — actuellement placeholder. Point ouvert : pas d'API JSON-RPC de désinstallation
   propre, solution de repli prévue via la fenêtre native `AddonInformation`.
5. **Akasha Store** : manifeste JSON curaté d'addons/dépôts installables depuis Aura.
