# Akasha OS — system-wide audit (October 2026)

Scope: everything outside the Plex-parity effort — addons, services,
systemd units, installer, repo↔Pi drift, logs and resource use.
Method: repo inventory + live inspection of the Pi (192.168.3.77),
risk-ordered review planned with Claude, every claim verified against
the real device before acting.

## Code health

- `aura_window.py` / `aura_detail.py`: deprecated `setInfo('video')` +
  `resumetime`/`totaltime` properties replaced by Kodi 20+
  `InfoTagVideo` (`setResumePoint`, typed setters). Legacy path kept as
  fallback for stubbed unit tests.
- `service.akasha.overlay`: the 1 Hz stats loop forked an `i2cget`
  subprocess every second for the fan — now cached 15 s.
- `plugin.video.themoviedb.helper` log spam (3 `GetDirectory` errors
  every 10 min): the skin enables the helper but its `addon_data`
  subdirs were never created — created `log_tagger/`, `log_library/`,
  `timer_report/` once on the Pi; durable fix.

## Services reviewed — OK as-is

- `service.akasha.remote` — battery-only scope is deliberate
  (`docs/remote/decisions.md`); bounded `bluetoothctl` call, 5 min poll.
- `service.akasha.ambient` — single long-lived AmbientWindow + Monitor
  IPC is the documented fix for Kodi's ~100 script-window ID pool.
- `service.akasha.splash` — boot-only update check, bounded retries.
- `script.akasha.quickstart` — completion marker + progressive resume
  + Settings relaunch all correct.
- `service.akasha.aura` — boot/Home handling fixed in 21ac0a8.

## Decisions

- **Voice** (`feature/voice-commands`, `script.akasha.voice`): parked —
  the remote's mic uses an undocumented proprietary Amazon BLE
  protocol; nothing to drive it with. Branch kept for reference.
- **PM4K / script.plexmod**: kept as a developer escape hatch, still
  wired in Guide ▸ Options développeurs ▸ "Lancer PM4K".
- **CEC**: `CEC_DISABLED` marker governs all CEC units; the Guide's
  developer menu can toggle it (writes the marker, flips the systemd
  units and Kodi's `activate_source` setting).
- **Jellyfin**: addon still installed but disabled on the Pi (token
  lost during an earlier settings wipe) — needs one interactive
  sign-in from the UI, then can be re-enabled.

## Known live issue at audit time

Pi↔Plex connectivity runs through the laptop's USB-Ethernet NAT
(`10.99.0.1/24`). When that adapter loses its link, the Pi reports
"No route to host" for `192.168.100.133` and Aura shows its loading
error. Physical link — requires the cable/adapter to be reseated.
